# G0.4 Runtime HUD Audit

## Root causes (hardware `?build=g04`)

| ID | Cause | Evidence | Fix |
| --- | --- | --- | --- |
| R1 | `MobileWebBootTelemetry` enabled for all mobile Web | `_should_show()` returned `PlatformService.mobile` | Gate on `?diag=1` only |
| R2 | `GameplayHud` hid mobile-critical regions | `_nav_row.visible = not mobile`, chat/left status hidden | MOBILE_LANDSCAPE keeps full HUD |
| R3 | Desktop/mobile combat cluster split | Tiny mobile cluster at corner | Single cluster sized by normalized ratios |
| R4 | Layout used shrink-desktop semantics | Small base sizes + hidden regions | `HudLayoutProfile` normalized measurements |

## Stale build

**NO** — export matched `814f112` source. Failure was runtime layout policy, not stale PCK.

## Wrong HUD owner

**NO** — `GameplayHud` is the single owner (`gameplay_hud_root` group). `FloatingPlayerHUD`, `MobileControls`, `Minimap`, `WorldLabelService` are child layers with defined roles.
