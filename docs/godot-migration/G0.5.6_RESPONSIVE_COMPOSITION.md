**MASTER VISUAL REFERENCE IS RESOLUTION-INDEPENDENT.**

Device logical viewport is the layout authority. Master defines hierarchy; device defines dimensions.

## Frozen foundation (unchanged)

- `WebViewportContract`
- `ResponsiveHudMetrics.logical_ui_viewport_size()` / `render_viewport_size()`

- `PHONE_LANDSCAPE` profile detection
- `CONTENT_SCALE_MODE_DISABLED` Web strategy

## G0.5.6 changes

### Per-component phone ratios (not global shrink)

| Zone | G0.5.5 | G0.5.6 |
| --- | --- | --- |
| Profile width | 14% | 11% |
| Status width | 23% | 16% |
| Mission | 20% × 24% full width | profile column × 16% height |
| Minimap | 20% short edge | 14% short edge |
| Chat height | 26% | 18% |
| FEUER | 20% × 1.32 cluster | 15% × 1.0 cluster |
| Combat cluster scale | 1.32 | 1.0 |

### Top band contract

`[PROFILE][STATUS][NAV][MINIMAP]` — no overlap at 754×297.

Mission constrained to profile column width so it cannot intrude under status.

### Visible content bounds

`VisibleContentBounds` recursively unions visible Control descendants per zone.

QA (`?qa=1`) reports:
- `PROFILE_CONTENT`, `STATUS_CONTENT`, `NAV_CONTENT`, etc.
- `PLAYER_SAFE_AREA`
- `OVERLAP_COUNT`

### Player safe area

`ResponsiveHudMetrics.player_safe_area()` — central gameplay readability region.

Consumables and combat must stay outside this region on phone.

### Navigation

Phone: 7 priority entries (Ships, Werft, Events, Quests, Guild, Chat, Menu).

Desktop/tablet: full 12-entry band.

### World labels

- Edge clamp in `world_label.gd`
- Priority collision avoidance in `world_label_service.gd`
- PLAYER > TARGETED NPC > OTHER NPC > POI
