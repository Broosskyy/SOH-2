# G0.5.2 Native Responsive Gameplay HUD

## OLD MODEL (G0.5 / G0.5.1)

- Project design viewport **1920×1080** with Web `content_scale_mode = viewport`
- HUD laid out in internal render pixels while browser displayed a smaller CSS canvas
- G0.5.1 added `css_to_render()` to inflate touch targets — a coordinate hack, not native responsiveness
- Manual per-frame layout without idempotent resize handling
- Minimap positioned outside presentation zone tree

## NEW MODEL (G0.5.2)

- **`ResponsiveHudMetrics`** is the single authority for viewport size, profile, margins, touch sizes, and fonts
- Web uses **`content_scale_mode = disabled`** and syncs `Window.size` to browser `innerWidth/innerHeight`
- HUD layout uses **actual Godot UI viewport** coordinates — one native UI space
- **`GameplayPresentationRoot`** fills available rect (`FULL_RECT`, `scale = Vector2.ONE`)
- Semantic **zone Controls** are direct children: ProfileZone, StatusZone, NavZone, etc.
- Layout recomputes **once per viewport change** (idempotent)
- CSS / DPR logged in `?qa=1` only — **never** used for Control positioning

## Content scale strategy

| Platform | Mode | Rationale |
| --- | --- | --- |
| Web | `disabled` + browser window sync | UI viewport = available canvas pixels |
| Desktop | Project default + window override | Responsive to actual window size |

3D world continues in the same scene; camera aspect follows viewport naturally. No SubViewport split in G0.5.2.

## Profile selection

Geometry-based (not OS mobile flag alone):

- **PHONE_LANDSCAPE**: landscape, aspect ≥ 1.55, short edge ≤ 520px
- **DESKTOP_TABLET**: everything else

## Sizing basis

```
size = clamp(viewport_axis * ratio, min_touch, max_ratio * axis)
font = clamp(short_edge * ratio, min_px, max_px)
```

No global `Control.scale` multiplier.

## Fullscreen / browser mode

- `fullscreenchange` and `resize` trigger `ResponsiveHudMetrics.apply_web_window_size()` and `size_changed`
- Safe area via `PlatformService.safe_rect(actual_viewport)`

## Why DPR is not manually applied

`devicePixelRatio` is diagnostic only. Physical pixel translation is owned by the browser canvas + Godot window mapping.

## Why css_to_render was removed

It positioned HUD in a hybrid coordinate space. G0.5.2 uses Godot UI coordinates exclusively.
