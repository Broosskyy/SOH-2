# G0.5.4 Logical UI Space

## Problem

On Mobile Web, Godot's render viewport (canvas backing buffer) is DPR-scaled
(~2123×838) while the visible browser game area is logical CSS (~755×298).
G0.5.2/G0.5.3 sized HUD from the render buffer, causing `DESKTOP_TABLET`
profile selection and microscopic controls.

## Spaces

| Space | Source | Used for |
| --- | --- | --- |
| CSS logical | `visualViewport` / canvas CSS rect | Profile, layout, fonts, touch sizing |
| Canvas buffer | `canvas.width/height` | Diagnostics only |
| Render viewport | Godot `get_visible_rect()` | 3D rendering, unproject positions |
| HUD logical | `logical_ui_viewport_size()` | All semantic HUD layout |
| Presentation scale | `render / logical` (measured) | Single root transform |

## Architecture

```
CanvasLayer (GameplayPresentationRoot)
└── PresentationRoot
    size = logical (e.g. 755×298)
    scale = presentation_scale (e.g. 2.81)
    └── zones laid out in logical coordinates
```

DPR is diagnostic only. Layout never multiplies by `devicePixelRatio` directly.

## G0.5.3 preserved

Full-viewport HTML/CSS, `WebViewportContract`, adaptive canvas policy, no
`Window.size` feedback loop.
