# G0.5.1 UI Metrics Audit

## ROOT CAUSE

G0.5 laid out HUD widgets using **small absolute pixel constants** (`150px` profile, `28px` nav, `11px` fonts) multiplied by `PresentationLayout.ui_scale()` (~1.0 on mobile).

On Samsung Mobile Web:

- Godot **render viewport** stays at project design size **1920×1080** (`content_scale_mode = viewport`).
- Browser **CSS viewport** is ~**915×412** landscape (varies by device/chrome).
- The canvas is uniformly downscaled by factor **~0.38–0.56** for display.
- HUD controls sized at 24–150 render px therefore appear as **9–70 CSS px** — below Master occupancy and touch targets.
- This is **not** a missing feature; it is **undersized layout in render space** plus missing **CSS→render conversion** for minimum touch targets.

`PresentationLayout.ui_scale()` also applied a redundant mobile normalization (`short_edge / 607`) that did not correct the CSS/render mismatch.

## DOUBLE SCALE

**YES** (conceptual):

1. Uniform browser canvas downscale (expected, affects world + UI equally)
2. **Additional** HUD undersizing from absolute px constants far below `HudLayoutProfile` Master ratios

**NO** DPR double-multiply: `UiMetrics` does not multiply by `devicePixelRatio`.

## FIX (G0.5.1)

Single authority: **`UiMetrics`**

- Layout coordinates: Godot render viewport (unchanged)
- Zone sizes: `HudLayoutProfile` **ratio** dimensions (Master occupancy)
- Touch/fonts: `UiMetrics.css_to_render(48, render)` for minimum render-pixel touch targets
- `PresentationLayout.ui_scale()` → `UiMetrics.effective_ui_scale()` = **1.0** (no second shrink)

## TARGET OCCUPANCY (1920×1080 render reference)

| Element | Ratio | Render px | CSS px @ 412h |
| --- | --- | --- | --- |
| Profile width | 0.12 | 230 | ~88 |
| Top bar height | 0.072 | 78 | ~30 |
| Minimap diameter | 0.17 | 184 | ~70 |
| FIRE button | 0.11 | 119 | ~45 |
| Nav button height | ~0.06+ | ≥126 touch floor | ≥48 CSS |
