# G0.6 — Gameplay HUD V2 Clean Rebuild

## Why the legacy HUD was frozen

G0.5.x introduced a reserved-region layout solver, content containment passes, deferred reflow, and minimum-size compensation. Real Samsung hardware at ~802×384 still showed overlap, overflow, wrong hierarchy, and clipped controls.

Incremental patching could not stabilize composition. G0.6 replaces only the **gameplay HUD presentation layer**.

## Active vs legacy

| System | Status |
|--------|--------|
| `GameplayHUDV2` (`gameplay_hud_v2.gd`) | **Active** in `World.tscn` |
| `GameplayPresentationRoot` (`gameplay_presentation_root.gd`) | **LEGACY** — kept for reference, not mounted |

Only one gameplay HUD runs at runtime.

## V2 architecture

```
CanvasLayer (GameplayHUDV2)
└── HudV2Root
    ├── ProfileBlock
    ├── StatusBlock
    ├── NavigationBlock
    ├── MinimapBlock
    ├── MissionBlock
    ├── ZoomBlock
    ├── MovementBlock
    ├── ChatBlock
    ├── ConsumablesBlock
    ├── CombatBlock
    └── FloatingHudLayer (reserved; 3D player bars remain in FloatingPlayerHUD)
```

**Screen-level layout:** `HudV2Layout.solve(logical_viewport)` assigns explicit block rects in logical UI coordinates.

**Internal layout:** Each widget block uses Containers only inside its assigned rect.

## Responsive principles

- **Authority:** `ResponsiveHudMetrics.logical_ui_viewport_size()` — not render buffer, DPR, or fixed design resolution.
- **Master visual reference:** Resolution-independent hierarchy guide only.
- **Phone landscape first:** 754×297, 802×384, 915×412, 932×430 — then tablet/desktop.
- **No global HUD scale:** Per-block min/max and semantic font tiers (`HudV2Typography`).
- **Ultrawide phones:** Widen horizontal spacing; keep vertical bands thin.

## Preserved systems (unchanged)

- WebViewportContract, presentation transform, logical/render separation
- Camera3D (FOV 35°, pitch, distance)
- Kraken scale 52, waterline 20.5
- World composition, navigation gameplay, input architecture
- FloatingPlayerHUD world-space player label
