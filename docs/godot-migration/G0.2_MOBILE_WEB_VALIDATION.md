# G0.2 Mobile Web Validation

Baseline: `134b4b4`. Runtime target: Godot 4.7.2, GL Compatibility.

## Evidence tiers

- **VERIFIED** — observed on the named physical target or directly reviewed
  from a reliable native run.
- **EMULATED** — observed through desktop browser/device emulation; useful for
  interaction checks but not hardware sign-off.
- **EXPORT_ONLY** — an export artifact was produced or measured, without a
  target-hardware runtime result.
- **UNAVAILABLE** — the required host, device or tooling was not available.

## Secure Context blocker (2026-08-29)

Godot 4.7.2 Web always requires a browser **Secure Context** before boot.
`Engine.getMissingFeatures()` checks `window.isSecureContext` unconditionally;
this is not tied to thread support, PWA/service worker registration, clipboard,
or orientation APIs in the current export.

| Check | Current export | Secure Context required? |
| --- | --- | --- |
| WebGL2 | enabled | no (works on HTTP, but Godot still blocks) |
| Fetch / WASM boot | enabled | no |
| Secure Context gate | always on | **yes** |
| Thread / SharedArrayBuffer | **disabled** (`variant/thread_support=false`) | only if threads enabled |
| Cross-Origin Isolation headers | present in template, threads off | only if threads enabled |
| PWA / Service Worker | empty `serviceWorker` | no |
| AudioWorklet | available when secure | audio falls back without worklet |
| Virtual keyboard (`experimentalVK`) | enabled | benefits from secure context on some browsers |
| Touch / mobile controls | runtime GDScript | no extra browser gate |

Why desktop localhost worked but Android LAN HTTP failed:

- `http://127.0.0.1:8061/index.html` is a **secure context** (browser localhost exception).
- `http://192.168.x.x:8061/index.html` on a phone is **not** a secure context.

Production Mobile Web must therefore be served over normal HTTPS. LAN hardware
testing must use the local HTTPS dev server, not plain HTTP on a LAN IP.

### HTTP vs HTTPS export decision

| Option | Mobile LAN test | Production fit | Decision |
| --- | --- | --- | --- |
| A) HTTP-compatible export | Would still fail: Godot 4.7 Web enforces Secure Context regardless of disabled thread/PWA options | incompatible with real mobile browsers off localhost | **reject** |
| B) HTTPS export + HTTPS hosting | works once the phone trusts or bypasses the dev certificate | matches production architecture | **adopt** |

No Godot export-preset change removes the Secure Context requirement without
breaking the supported 4.7.2 Web boot path.

## Local and LAN preview

Start the dual static server from the repo root:

```bash
npm run serve:godot:web
```

This binds:

- Desktop QA HTTP: `http://127.0.0.1:8061/index.html`
- Local HTTPS: `https://127.0.0.1:8062/index.html`
- LAN Mobile HTTPS: `https://<LAN-IP>:8062/index.html` (auto-printed at startup)

Validated endpoints on 2026-08-29:

- Local HTTP (desktop QA): `http://127.0.0.1:8061/index.html`
- Local HTTPS: `https://127.0.0.1:8062/index.html`
- LAN HTTPS at validation time: `https://192.168.178.144:8062/index.html`

The LAN address is environment-specific and must be rediscovered for future
runs (`npm run serve:godot:web` prints `MOBILE_HTTPS_URL`).

Development TLS uses a repo-local self-signed certificate in `.dev-certs/godot-web/`
(regenerated when the detected LAN IPv4 changes). This is for LAN hardware
testing only, not production hosting.

### Android one-time dev certificate steps

1. Connect the phone to the same Wi‑Fi as the dev machine.
2. Start `npm run serve:godot:web` on the PC and open the printed
   `MOBILE_HTTPS_URL` in Chrome on the phone.
3. On the certificate warning screen, choose **Advanced** → **Proceed to
   &lt;LAN-IP&gt; (unsafe)**. This accepts the self-signed dev certificate for
   that host until it is regenerated.
4. Confirm Godot clears the splash and the canvas renders; then run the
   physical validation checklist below.

Do **not** rely on Chrome flags or permanent HTTP exceptions for production or
long-term architecture.

## Emulated capture rule

When browser emulation produces a black capture while the Godot engine/runtime
is demonstrably live, classify the visual evidence as
**CAPTURE_UNRELIABLE**. This result is neither a visual PASS nor evidence that
the runtime failed. Record engine/runtime evidence separately and repeat visual
validation on physical hardware.

## Physical validation checklist

The following remain pending after the Secure Context fix:

- launch and first-frame rendering in a real mobile browser over **HTTPS LAN**;
- stable GL Compatibility rendering during movement and camera pan;
- tap-destination navigation, left camera-pan joystick and pinch zoom;
- shared safe-area behavior for HUD and controls in portrait/landscape and
  around device cutouts;
- Kraken readability, wake placement and HUD clearance at all headings;
- sustained frame time, memory pressure and thermal behavior;
- Android install/launch/runtime checks through a working device toolchain;
- iOS browser/native checks on an available Apple host and device.

Record device model, OS/browser version, orientation, evidence tier, measured
performance and capture reliability for every future run.
