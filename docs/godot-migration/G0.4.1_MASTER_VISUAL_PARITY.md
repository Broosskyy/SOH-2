# G0.4.1 — Master Visual Parity Recovery

## Canonical Reference

**MASTER_VISUAL_REFERENCE** is the canonical gameplay presentation reference from G0.4.1 onward unless explicitly superseded.

This pass does **not** embed the master image as runtime art. All HUD and world elements remain real Godot runtime components.

## Current Hardware Baseline

The Samsung Chrome landscape capture (CURRENT_HARDWARE_BASELINE) showed:

- Full-width HUD panels creating giant dark rectangles
- Top navigation consuming excessive screen height
- Oversized chat and bottom dock region selector
- Combat controls overlaying large transparent areas
- Player and NPCs visually too small relative to world
- Water too dark and flat
- Debug/prototype UI density instead of master composition

## HUD Architecture Changes

Previous structure used monolithic `PanelContainer` nodes stretched to viewport fractions.

G0.4.1 semantic anchor zones:

| Zone | Node | Position |
| --- | --- | --- |
| TOP_LEFT | `_profile_zone` | Safe top-left, content-sized |
| TOP_STATUS | `_status_zone` | Safe top-center |
| TOP_NAV | `_nav_row` | Safe top-right |
| LEFT_UPPER | `_mission_panel` | Below profile |
| LEFT_MIDDLE | `_zoom_panel` | Below mission |
| BOTTOM_LEFT | `_chat_panel` | Above consumables |
| BOTTOM_CENTER | `_consumables_row` | No background panel |
| BOTTOM_RIGHT | `_combat_cluster` | Safe bottom-right |
| TOP_RIGHT | `Minimap` | Child CanvasLayer, unchanged data-driven 2D |

Helper `_fit_control()` sizes panels to combined child minimums instead of viewport spans.

## Viewport / Fullscreen

- Stretch mode remains `canvas_items` at 1920×1080 design resolution
- `PlatformService.safe_rect()` maps display safe area into viewport coordinates
- Fullscreen via `_fullscreen_button` → user gesture only (Web `requestFullscreen`)

## Responsive Strategy

- `HudLayoutProfile.detect()` → DESKTOP / MOBILE_LANDSCAPE / MOBILE_PORTRAIT
- Semantic scale caps reduced for mobile landscape (max ~1.12 vs prior 1.35)
- Samsung ~1080×607 class used as calibration reference, not hardcoded
- Desktop and mobile share the same information hierarchy

## Player / World Scaling

- Kraken `visual_scale = 52.0` unchanged
- `DEFAULT_CAMERA_ZOOM` 0.90 → 0.94
- NPC visual root 0.62 → 0.72
- Landmark island visual scale 0.38 → 0.42

## Water Changes

`ocean_surface.gdshader`:

- `u_deep`: `(0.02, 0.18, 0.38)`
- `u_shallow`: `(0.08, 0.42, 0.58)`

Mobile-web compatible; no desktop-only reflection systems added.
