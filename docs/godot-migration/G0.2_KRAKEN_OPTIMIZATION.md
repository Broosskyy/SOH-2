## G0.2 disposition

Blender and `gltfpack` were unavailable in the validation environment. The
source GLB is therefore preserved unchanged and the optimization status is
**LOD=STRATEGY**, not complete.

| Level | Geometry target | Texture target | Intended use |
| --- | ---: | ---: | --- |
| LOD0 | Current 30,744 tris | Current source | Near hero/native desktop |
| LOD1 | 12k–18k tris | 2048 maximum | Normal gameplay/mobile native |
| LOD2 | 4k–8k tris | 1024 maximum | Distance/Mobile Web |

Future authored LODs must preserve bow/stern identity, the 180-degree visual
yaw correction, waterline placement, wake alignment and readable silhouettes.
Texture work should retain mipmaps and evaluate platform-appropriate
compression and MR channel packing.

## Packaging decision

The final Web PCK is 20,311,756 bytes. Kraken accounts for approximately 86%
of it using the prior imported-cache measurement. `all_resources` remains
enabled for G0.2 because the runtime uses dynamic catalog/filter selection and
premature resource stripping could omit required assets.

Transition plan:

1. inventory every dynamically selected resource and convert selection to
   explicit dependency references or a generated include manifest;
2. produce and visually approve authored LOD1/LOD2 assets;
3. apply target texture limits and compression;
4. export with an explicit resource inclusion policy;
5. compare PCK contents, startup behavior and all catalog/filter paths;
6. remove `all_resources` only after those checks pass.

The original source must remain available as rollback material throughout this
work.
