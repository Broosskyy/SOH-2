# G0.5.3 Mobile Web Canvas Recovery

## ROOT CAUSE

G0.5.2 correctly made the HUD responsive to the Godot UI viewport, but on real Samsung hardware the **HTML canvas did not fill the browser content area**. The game rendered into a small rectangle (~755×298) at the bottom-left while most of the page stayed black.

`apply_web_window_size()` synchronized Godot `Window.size` to `innerWidth/innerHeight` while the exported HTML shell did not enforce a full-viewport CSS contract on `html`, `body`, and `#canvas`. Godot's internal window shrank to match partial browser metrics, but the canvas element was not stretched to occupy the available page.

## Fix

1. **Custom Web shell** (`godot/export/web_shell.html`) — `html/body/canvas` fill 100% viewport; canvas `position: fixed; inset: 0`.
2. **`web-viewport-contract.js`** — enforces fill on resize/orientation/fullscreen/`visualViewport` changes; exposes metrics for QA.
3. **`WebViewportContract` autoload** — central resize sync; bridges JS events to Godot via `JavaScriptBridge.create_callback`.
4. **`ResponsiveHudMetrics.apply_web_presentation_sync()`** — uses `visualViewport` when available; syncs Godot window only when it diverges from browser content size.
5. **Post-export patch** — copies contract JS and injects build marker into `godot/build/web/`.

## Content scale mode

Web remains `CONTENT_SCALE_MODE_DISABLED`. Canvas resize policy stays **adaptive (2)**. Presentation size is owned by the HTML/CSS contract + Godot adaptive resize; DPR is diagnostic only.
