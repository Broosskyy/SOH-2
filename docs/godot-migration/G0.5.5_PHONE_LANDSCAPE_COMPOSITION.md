# G0.5.5 Phone Landscape Composition

## Hardware baseline

Real Samsung G0.5.4 screenshot (`755×298` logical):

- `PHONE_LANDSCAPE` profile: **PASS**
- Logical/render separation: **PASS**
- Canvas fill: **PASS**
- Composition / occupancy: **FAIL** (widgets too large, overlapping, center obstructed)

## What changed (G0.5.5)

**Not changed:** `ResponsiveHudMetrics`, logical UI viewport, render viewport, root presentation transform, `WebViewportContract`, canvas recovery.

**Changed:** PHONE_LANDSCAPE-only occupancy ratios, font tiers, combat cluster layout, ASCII-safe HUD labels, world-label scale, central safe-area QA.

## Widget sizing (phone)

| Zone | Target occupancy |
| --- | --- |
| Profile | ~14% width, compact top bar |
| Status | ~23% width, compact 3-bar stack |
| Nav | single compact row between status and minimap |
| Mission | ~20% × ~24%, upper-left secondary |
| Minimap | ~20% short-edge diameter |
| Chat | ~22% × ~26%, bottom-left |
| Consumables | ~11% short-edge diameter each |
| FEUER | ~20% short-edge diameter, clustered abilities |

## Font tiers

1. **Primary** — profile, status, floating player
2. **Secondary** — mission, chat, nav, combat secondary
3. **Tertiary** — world labels, NPC metadata

## Broken glyph replacements

Unicode emoji/symbols replaced with ASCII abbreviations in active gameplay HUD (`GameplayPresentationRoot`): nav letters, `OIL/POT/BMB/H2O`, `FEUER`, `FS`, `G/P` currency prefixes.

## Overlap contract

At `755×298`, `915×412`, `932×430`:

- No major overlap between profile/status/nav/minimap/mission/chat/combat pairs
- Combat, chat, minimap remain inside viewport
- Central safe area mostly unobstructed (≤1 minor zone intrusion)

## Central safe area

`ResponsiveHudMetrics.central_safe_rect()` — gameplay readability region; QA reports `CENTRAL_SAFE_AREA` under `?qa=1`.
